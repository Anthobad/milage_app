# AI Development Rules

## General

R1. Follow the existing architecture. Do not redesign the project structure without approval.

R2. Read relevant files in /docs before implementing features.

R3. Prefer simple solutions. Do not over-engineer.

R4. Do not add dependencies unless they are necessary and approved.

---

## Code

R5. Keep UI separate from business logic.

R6. Reuse existing components before creating new ones.

R7. Avoid duplicate code.

R8. Keep files focused and organized.

R9. Use clear and consistent naming.

---

## Flutter

R10. Follow Flutter best practices.

R11. Use Riverpod for application state.

R12. Use GoRouter for navigation.

R13. Follow the existing feature-first structure.

---

## Features

R14. Implement one feature at a time.

R15. Do not modify unrelated features.

R16. Before large changes, explain the approach.

R17. Preserve existing functionality.

---

## UI

R18. Follow TripRank design guidelines.

R19. Keep interfaces simple and driving-focused.

R20. Avoid unnecessary screens and interactions.
